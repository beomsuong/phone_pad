# 요청 — 서버 GUI 창 디자인 현대화 (순수 스타일링, 동작 무변경)

## 범위 판단: **단일 사이드(서버)** — 와이어 프로토콜 무변경, protocol-qa 생략

사용자 요청(그대로): "gui 디자인이 너무 레트로한데 좀 모던하게 바꿔봐". **순수하게 시각적인 리스타일링**이다 — 버튼이 하는 일, 상태 변수 키, 트레이-축소 동작, 갱신 주기 등 **기능은 단 하나도 바뀌면 안 된다**. 지금 `gui.py`가 클래식 `tk.Label`/`tk.Button`/`tk.Frame`을 쓰고 있어서(Windows 기본 회색 버튼, 베벨 테두리) "레트로"하게 보인다.

공통 금지: 커밋 금지, `AGENTS.md`/`CLAUDE.md` 수정 금지(리더가 함), `git stash`/`checkout`/`reset` 금지. 범위는 `pc_server/`만.

## 방향 (확정, 임의로 바꾸지 말 것)

**새 pip 의존성을 추가하지 않는다** — `AGENTS.md` 컨벤션("서버 쪽 새 UI 기능도 필수 의존성을 늘리지 않는다")을 그대로 지킨다. `ttkbootstrap`/`sv-ttk`처럼 예쁘게 해주는 서드파티 패키지가 있지만 쓰지 않는다. 대신:

1. **`tkinter.ttk`로 전환** — 지금 쓰는 `tk.Frame`/`tk.Label`/`tk.Button`을 각각 `ttk.Frame`/`ttk.Label`/`ttk.Button`으로 바꾼다(표준 라이브러리, 추가 설치 없음). `ttk.Style().theme_use("vista")`를 적용한다(Windows 네이티브 테마 — Aero 스타일 버튼/여백으로 클래식 tk보다 훨씬 현대적으로 보인다). 이 환경이 아닌 다른 플랫폼(테스트 실행 환경 등)에서 "vista"가 없을 수 있으니 `style.theme_names()`에 있는지 확인하고 없으면 조용히 기본 테마로 폴백한다(예외로 창 생성이 깨지면 안 됨).
2. **PIN을 "인증 코드"처럼 크게 보여준다** — 지금은 다른 라벨과 같은 10pt다. PIN 전용 스타일(`ttk.Style` 커스텀 스타일, 예: `"Pin.TLabel"`)로 큰 폰트(대략 28~32pt), 굵게, 등폭에 가까운 폰트("Consolas")를 써서 숫자가 또렷하게 보이게 한다. 인증이 꺼져 있을 때(`gui_state`가 이미 처리하는 "인증 꺼짐" 문구)는 이 큰 스타일을 적용하지 않아도 된다(짧은 문구에 32pt는 안 어울림) — 상태에 따라 스타일을 다르게 적용해도 좋다.
3. **연결 상태를 색으로도 보여준다** — 지금은 텍스트만 있다("대기 중" / "연결됨 (N대)"). 트레이 아이콘이 이미 회색=대기/초록=연결됨 색 규칙을 쓰고 있으니(`tray.py`/`tray_status.py` 참조) **같은 색 의미를 창에도 맞춘다**: 상태 문구 앞에 작은 색 원(유니코드 `●` 같은 글자를 색만 입혀 써도 된다 — Canvas로 진짜 도형을 그릴 필요는 없다) 또는 상태 라벨 자체의 `foreground` 색을 회색/초록으로 바꾼다.
4. **여백과 구조 정리** — 지금 `PAD_X=18, PAD_Y=12`를 좀 더 넉넉하게(예: 24/16 근처, 정확한 값은 판단해서 정할 것), 섹션 사이 간격을 규칙적으로. 버튼 두 개(시작/정지 토글, 종료)는 지금처럼 좌우로 배치하되, 시작 액션 쪽에 강조 스타일을 시도해 본다 — ttk의 `"Accent.TButton"`은 최신 Tcl/Tk(8.6.13+)의 vista 테마에서만 있는 스타일이라, 있으면 쓰고 없으면(구버전 Tcl/Tk) 예외를 잡고 기본 스타일로 조용히 폴백한다(크래시 금지, 이 환경의 Tcl/Tk 버전을 확인해서 실제로 되는지 실측할 것).
5. **창 아이콘(선택, 시간 되면)** — `tray.py`의 `create_icon_image()`가 이미 PIL로 트레이 아이콘 이미지를 만든다. Pillow가 설치돼 있으면 그 이미지를 재사용해 `root.iconphoto()`로 창 아이콘도 맞출 수 있다. Pillow가 없으면(선택 의존성이므로) 조용히 건너뛴다. **이건 있으면 좋고 없어도 되는 항목** — 위 1~4번이 우선이다.
6. **동작은 절대 바꾸지 않는다**: 버튼 콜백(`on_toggle`/`exit_clicked`/`on_close`), `_vars` 딕셔너리 키("status"/"address"/"pin"/"message"/"hint"/"toggle"), `refresh()`/`current_labels()`/`close_hint()` 등 `gui_state.py`와의 계약, X 버튼이 트레이로 숨는 동작, 갱신 주기(`DEFAULT_POLL_INTERVAL_S`/`DEFAULT_QUEUE_INTERVAL_S`) 전부 무변경. 이번 작업은 **`build()` 메서드 안의 위젯 생성/배치 코드와 그 스타일만** 건드리는 것이 목표다.

## 테스트

1. **`pc_server/tests/fake_tk.py`(기존)를 확장**: 지금은 `tk.Frame`/`tk.Label`/`tk.Button`/`tk.StringVar`/`tk.Tk`의 가짜를 제공한다. `ttk`로 전환하면 `build()`가 `self._tk.ttk.Frame` 등을 참조하게 될 텐데(또는 별도로 `ttk` 모듈을 주입받게 만들 수도 있음 — 설계는 판단해서 정할 것, 기존 `tk_module` 주입 패턴과 일관되게), 그 경로도 fake가 커버해야 기존 `test_gui_adapter.py`가 디스플레이 없이 계속 통과한다.
2. **기존 `test_gui_adapter.py`/`test_gui_state.py`/`test_server_gui.py`는 전부 무수정으로 통과해야 한다**(동작 계약이 안 바뀌었으므로) — 단, fake 객체가 `ttk` 관련 속성/클래스를 지원하도록 fake_tk.py 자체를 넓히는 것은 괜찮다(테스트가 검증하는 *동작*은 그대로 두고 *구현 디테일*만 따라가는 것이므로).
3. `python -m pytest` 기준선 **702 passed, 1 skipped** → 회귀 0.
4. **실제로 눈으로 확인할 것**: 이 환경(개발자의 실제 Windows 데스크톱)에서 `python server.py`를 실제로 띄워 창이 실제로 어떻게 보이는지 확인하고(vista 테마가 실제로 적용됐는지, PIN이 크게 보이는지, 상태 색이 바뀌는지 — 시작 전/시작 후 두 상태 다), **가능하면 창을 캡처한 스크린샷 파일을 저장소 밖 스크래치패드에 남겨** 리더가 확인할 수 있게 할 것(예: PowerShell의 `System.Drawing`/`System.Windows.Forms`로 창을 캡처하는 방법을 조사해서 시도 — 안 되면 시도한 방법과 실패 사유를 요약에 적고 대신 코드로 어떤 스타일이 적용되는지 최대한 자세히 설명할 것. 스크린샷은 **필수는 아니지만 강력히 권장**한다 — "모던하게 보이는가"는 코드만 봐서는 판단할 수 없는 주관적 항목이라 시각 확인이 중요하다).
5. 확인 후 반드시 띄운 프로세스를 정리하고 포트를 반납할 것.
