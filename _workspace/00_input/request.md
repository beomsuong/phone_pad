# 요청 — PC 서버 GUI 창 (기본 모드로 승격)

## 범위 판단: **단일 사이드(서버)** — 와이어 프로토콜 무변경, protocol-qa 생략

사용자 결정(확인됨):
1. GUI 범위: **간단히** — PIN·접속 주소·연결 상태 + 시작/종료 버튼만(연결된 기기 목록·실시간 로그는 이번 범위 밖).
2. 창·트레이 관계: **둘 다** — 창이 기본이고, 창을 닫으면(X) 종료가 아니라 **트레이로 축소**된다. 트레이 아이콘에서 다시 창을 열 수 있다.

공통 금지: 커밋 금지, `AGENTS.md`/`CLAUDE.md` 수정 금지(리더가 함), `git stash`/`checkout`/`reset` 금지(다른 세션이 동시에 이 저장소를 쓸 수 있음 — 안전을 위해 습관적으로 금지). 저장소 루트 `C:\Github\phone_pad`, `.claude/worktrees/`는 무시. 범위는 `pc_server/`만.

## GUI 프레임워크: **tkinter** (표준 라이브러리)

이유를 스펙으로 못 박는다 — 임의로 다른 라이브러리(PyQt/Kivy 등)로 바꾸지 말 것: `pin_auth.py`/`discovery.py`처럼 이 프로젝트는 서버 쪽에 필수 의존성을 늘리지 않는 것을 원칙으로 해왔다(pystray/Pillow조차 **선택** 의존성이다). tkinter는 CPython에 기본 포함되어 새 `pip install` 요구사항이 생기지 않는다.

## 아키텍처 — 스레드 모델 (핵심 위험, 반드시 읽을 것)

지금까지 `run_with_tray`는 "pystray가 Windows에서 메시지 루프를 메인 스레드가 소유해야 한다"는 이유로 **트레이를 메인 스레드에, 서버를 백그라운드 스레드에** 두는 구조였다(`server.py:523-579`). 여기에 tkinter 창까지 더하면 세 번째 이벤트 루프가 필요하다. tkinter의 `mainloop()`도 반드시 메인 스레드에서 돌아야 하므로(이건 Tkinter의 강한 제약), 다음과 같이 뒤집는다:

- **tkinter `mainloop()`가 메인 스레드를 소유한다**(창이 앱의 중심이 되므로 자연스럽다).
- **pystray는 백그라운드 스레드에서 돈다.** pystray 공식 문서는 macOS(Cocoa) 백엔드는 메인 스레드가 필요하다고 명시하지만, 이 프로젝트는 **Windows 전용**이고 Windows(`_win32`) 백엔드는 자신이 만든 창이 속한 스레드에서 메시지 루프(`GetMessage`)를 돌리므로 꼭 메인 스레드일 필요가 없다 — 백그라운드 스레드에서 `icon.run()`을 호출해도 된다(실측으로 확인할 것 — 창을 띄운 채 트레이 아이콘이 실제로 나타나고 클릭에 반응하는지 사람이 눈으로 봐야 한다).
- 서버(TCP/UDP 소켓)는 **지금처럼 별도 백그라운드 스레드**에서 `ServerRuntime.run()`을 돈다 — 이 부분은 손대지 않는다.
- **시작/종료 버튼 때문에 서버 스레드는 "한 번 쓰고 버리는" 관계가 된다.** `ServerRuntime`은 `close()` 후 재사용하도록 설계되지 않았다(소켓은 한 번 닫으면 다시 못 연다) — "종료" 버튼을 누르면 현재 `ServerRuntime`을 멈추고 스레드를 정리한 뒤, "시작"을 다시 누르면 **새 `ServerRuntime` 인스턴스**를 만들어 새 스레드에서 돌려야 한다. 그래서 GUI 계층은 `ServerRuntime` 인스턴스가 아니라 **`ServerRuntime`을 만드는 factory 함수**(인자 없이 호출하면 새 인스턴스를 반환)를 받아야 한다.
- PIN: `--pin`으로 고정하지 않은 한, **"시작"을 다시 누를 때마다 새 PIN이 생성된다**(기존 원칙 "PIN은 세션마다"를 프로세스 재시작이 아니라 "서버 시작" 단위로 확장 — factory가 매번 `resolve_expected_pin()`을 다시 호출하면 자연히 이렇게 된다).

## 구현 지침

1. **`pc_server/tray_status.py`(기존 파일, 순수 로직) 재사용**: 이미 `tray_status()`, `format_address_label()`, `format_pin_label()`, `detect_lan_ip()`가 있다. GUI 창의 표시 텍스트(PIN, 접속 주소, 연결 상태)는 **이 함수들을 그대로 재사용**한다 — 새로 만들지 말 것(DRY, 이미 테스트돼 있음). GUI 전용으로 새로 필요한 순수 로직(예: 시작/종료 버튼에 표시할 라벨을 실행 상태로부터 결정하는 함수)만 이 파일에 추가하거나, 필요하면 작은 신규 순수 모듈(`gui_state.py`)을 만들어도 된다 — 판단은 맡긴다. 어느 쪽이든 **Tk를 import하지 않는 순수 함수**로 만들어 pytest로 커버할 것.
2. **`pc_server/gui.py`(신규)** — `tray.py`가 pystray 어댑터인 것과 같은 자리의 tkinter 어댑터:
   - 창 하나: 제목("Phone Pad Server" 등), PIN 라벨(인증 꺼져 있으면 "인증 꺼짐" 같은 문구 — `tray_status.format_pin_label`이 이미 `None`을 처리하는지 확인하고 없으면 맞출 것), 접속 주소 라벨(`IP:9000`), 연결 상태 라벨("대기 중" / "연결됨 (N대)"), **시작/종료 토글 버튼**(정지 상태면 "시작" 활성·"종료(Exit)" 별도 버튼은 항상 있음 — "시작/정지"와 "완전 종료(Exit)"는 다른 동작이니 버튼 2개: **정지/시작 토글 버튼** + **종료 버튼**), 연결 상태 라벨은 주기적으로(예: 1초 `after()` 폴링, 트레이의 기존 폴링 스레드와 같은 간격 참고) 갱신.
   - **정지 → 시작 실패**(포트 점유 등 `OSError`): 창에 에러 메시지를 라벨/다이얼로그로 보여주고 "정지됨" 상태를 유지한다 — 크래시하거나 창이 먹통이 되면 안 된다.
   - **X 버튼(창 닫기) 프로토콜**: `protocol("WM_DELETE_WINDOW", ...)`로 가로채 `destroy()` 대신 `withdraw()`(숨기기)를 호출 — **트레이가 사용 가능할 때만**. 트레이 아이콘 메뉴에 새 항목 "창 열기"(또는 기존 "상태" 항목 자리 근처)를 추가해 누르면 `deiconify()` + `lift()`로 창을 복원한다(tkinter는 스레드 세이프하지 않으므로, 트레이 스레드에서 직접 위젯을 건드리지 말고 tkinter의 `after()`/이벤트 큐를 통해 메인(=tkinter) 스레드에서 실행되게 할 것 — 안전한 스레드 간 호출 방법을 조사해서 쓸 것, 예: `root.after(0, root.deiconify)`는 다른 스레드에서 호출해도 되는지 확인 필요, 안 되면 `queue.Queue` + 주기적 `after()` 폴링으로 안전하게 만들 것).
   - **트레이가 사용 불가능(pystray/Pillow 미설치)할 때**: X 버튼은 곧바로 완전 종료(아래 "종료" 버튼과 동일 동작). 콘솔에 기존 경고 한 줄(`[!] pystray/Pillow not available - ...`)을 유지하되 "트레이로 축소할 수 없어 창을 닫으면 서버가 종료됩니다" 취지를 덧붙여도 좋다.
   - **"종료" 버튼**(그리고 트레이의 기존 "종료" 메뉴 항목): 서버가 돌고 있으면 멈추고(드래그 강제 해제 포함), 트레이 아이콘을 제거하고, tkinter 창을 `destroy()`하고, 프로세스를 정상 종료한다. **기존 `run_with_tray`의 `on_quit` 종료 절차(정지 → join → drag 해제 → 아이콘 제거)를 그대로 재사용**할 것 — 종료 경로를 두 번 구현하지 말 것.
3. **`server.py` 통합**: 새 실행 함수(예: `run_with_gui(controller, registry, runtime_factory, tray_factory=None, gui_factory=None, join_timeout=...)`)를 추가한다. `main()`의 모드 선택을 다음처럼 확장한다(플래그는 **재사용**, 새 플래그 추가하지 않음 — `--no-tray`의 의미를 "그래픽 UI(창+트레이) 전부 끄고 콘솔 모드"로 자연스럽게 확장):
   - `--no-tray` → 기존 `run_console`(무변경, 회귀 없어야 함).
   - 그 외(기본) → **tkinter를 import할 수 있으면** `run_with_gui`(창이 기본, pystray 있으면 트레이도 함께). **tkinter를 import할 수 없으면**(드묾, 하지만 일부 최소 Python 설치엔 tcl/tk이 빠져 있을 수 있음) 기존 `run_with_tray`로 폴백(트레이만, 창 없음) — 그것도 pystray가 없으면 기존처럼 `run_console`로 한 번 더 폴백(현재 `main()`의 기존 폴백 사슬과 동일한 정신, 층 하나만 추가).
   - 이 폴백 사슬은 실제로 각 단계를 재현해 검증할 것(예: 모듈을 못 찾은 것처럼 흉내 내는 테스트).
4. **`ServerRuntime` 생성 파라미터는 지금과 완전히 동일**하게(`--pin`/`--no-auth`/`--no-discovery`/`--allow-multiple`) `main()`이 결정해 factory 클로저에 캡처한다 — GUI에는 이 값들을 바꾸는 토글을 **추가하지 않는다**(사용자 결정: 간단 범위).
5. **`single_instance.py` 중복 실행 가드는 무변경.** 지금처럼 `main()` 맨 앞에서 체크되고, 중복이면 기존 `MessageBoxW`(windowed 빌드) 경고 후 종료 코드 2 — 이건 GUI 창을 만들기 **전**에 일어나므로 tkinter를 새로 건드릴 필요가 없다. 그대로 동작하는지만 확인할 것.

## 테스트

1. **순수 로직**(`tray_status.py` 확장분 또는 신규 `gui_state.py`): 기존 `test_tray_status.py`에 이어 붙이거나 신규 파일. Tk 임포트 없이 pytest로 전부 커버.
2. **`gui.py` 어댑터**: `tray_adapter` 테스트가 `icon_factory`/`image_factory`를 주입해 실제 pystray 없이 로직을 검증하는 것과 같은 패턴 — `gui.py`도 Tk 위젯 생성 지점을 주입 가능하게 만들어(또는 실제 `tkinter.Tk()`를 쓰되 `withdraw()` 상태로만 열어 화면에 아무것도 안 보이게 하고 즉시 `destroy()`하는 식으로) 자동 테스트가 실제 창을 화면에 띄우지 않고도 버튼 콜백 배선·상태 갱신 로직을 검증하게 할 것. **이 환경(개발자의 실제 Windows 데스크톱)에 디스플레이가 있으니 `tkinter.Tk()` 생성 자체는 될 것이나, CI처럼 디스플레이가 없는 환경에서도 안전하게 스킵되도록** 생성 실패 시 우아하게 처리하는 편이 좋다(pytest 컬렉션이 깨지지 않게).
3. **`run_with_gui`/폴백 사슬**: `run_with_tray` 테스트가 만들어져 있는 방식(가짜 `runtime`, 가짜 `tray_factory`)을 참고해 `run_with_gui`도 가짜 `gui_factory`로 구동 — 종료 절차(정지 → join → drag 해제 → 창/아이콘 정리)가 정확히 한 번씩 일어나는지, 시작 실패 시 크래시하지 않는지, 시작/정지를 여러 번 토글해도(각각 새 `ServerRuntime`) 정상 동작하는지.
4. **기존 테스트 회귀 없음**: `run_console`/`run_with_tray`/`main()`/single_instance 관련 기존 테스트는 전부 무수정으로 통과해야 한다(이번 변경은 새 모드를 추가하는 것이지 기존 모드를 바꾸는 게 아니다).
5. `python -m pytest` 기준선 **585 passed, 1 skipped** → 회귀 0.
6. **실제 확인(가능하면)**: 이 환경에서 실제로 `python server.py`를 실행해(백그라운드로 띄우고) 창이 뜨는지, 트레이 아이콘이 함께 뜨는지, X를 누르면 트레이로 숨는지, 트레이에서 다시 열리는지, 시작/정지 토글이 실제로 포트를 열고 닫는지 확인할 것(끝나면 반드시 프로세스를 정리하고 포트를 반납할 것 — 지난 실행들의 관례). PyInstaller 재빌드는 **이번 범위 밖**(모듈 추가 시 재빌드 필요하다는 것만 요약에 기록).
